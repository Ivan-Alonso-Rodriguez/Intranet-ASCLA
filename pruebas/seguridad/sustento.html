Evidencia de las cinco rutas. Los 401 de la API anónima y 404 de una ruta inexistente son respuestas esperadas; también deben evitar exponer versiones.

La configuración del repositorio config/security.conf ya contiene:

ServerTokens Prod
ServerSignature Off

Apache documenta ServerTokens como configuración global del servidor; con Prod envía únicamente «Apache». No se instala con el ZIP del plugin ni se aplica desde un perfil de WordPress. Ocultar la versión reduce información expuesta; no actualiza Apache ni corrige vulnerabilidades del servidor.

Solicitud concreta al responsable del hosting: «Aplicar ServerTokens Prod y ServerSignature Off al Apache que sirve wordpress.ingsoftware.lat, validar con apache2ctl configtest y recargar su configuración. Si hay proxy, comprobar la respuesta pública final. Después repetir el verificador HTTP y el de estáticos/API/errores; esperamos 20/20 y ninguna versión en Server».

En un despliegue con este repositorio, compose.yaml monta config/security.conf en /etc/apache2/conf-enabled/ascla-security.conf. El operador debe comprobar ese montaje y que la configuración esté cargada; no basta con subir el ZIP. En Debian/Apache, una vez instalado el archivo de configuración:

apache2ctl configtest
apache2ctl -k graceful

La recarga solo se realiza si el primer comando confirma Syntax OK; la persona con acceso al hosting debe conservar la configuración anterior para revertir si aparece un problema.

Recomprobar desde la raíz del repositorio, tras el cambio del hosting:

node scripts/check-server-exposure.cjs https://wordpress.ingsoftware.lat test-results/servidor-qa-despues.json
